# AutoDoor 行为树系统 — 详细实现方法

## 1 行为树节点类型实现

系统共包含 **24 种节点**：6 种复合节点、6 种条件节点、12 种动作节点。

### 1.1 节点基类 (Node)

所有节点的抽象基类，定义通用接口和默认行为：

```python
class Node(ABC):
    NODE_TYPE = "Node"                    # 类级别节点类型标识
    
    def __init__(self, node_id=None, config=None):
        self.node_id = node_id or uuid4()[:8]   # 唯一标识
        self.config = config or NodeConfig()     # 节点配置
        self.status = NodeStatus.SUCCESS         # 当前状态
        self.children: List[Node] = []           # 子节点列表
        self.parent: Optional[Node] = None       # 父节点引用
        self._tick_count = 0                     # tick计数
    
    @abstractmethod
    def tick(self, context: ExecutionContext) -> NodeStatus:
        """核心方法：执行节点逻辑，返回执行状态"""
        pass
```

**设计要点：**

- 使用 `uuid4()[:8]` 生成短 ID，兼顾唯一性与可读性
- `config` 使用 `NodeConfig` 数据类，采用扁平化结构存储节点参数
- `tick()` 是纯抽象方法，子类必须实现
- `reset(reset_counters=True)` 方法支持控制是否重置计数器，用于 retry/repeat 场景

**节点重置机制：**

| 场景   | 方法                           | 行为                          |
| ---- | ---------------------------- | --------------------------- |
| 完全重置 | `reset(reset_counters=True)` | 重置所有状态和计数器                  |
| 重试重置 | `_reset_for_retry()`         | 设置 `status=RUNNING`，保留重试计数器 |
| 重复重置 | `_reset_for_repeat()`        | 调用 `reset(False)`，保留重复计数器   |

**重要：** `_reset_for_retry()` 和 `_reset_for_repeat()` 必须将 `status` 设置为 `RUNNING`，确保节点在重试/重复期间返回正确状态。

**`_reset_for_retry()` 完整实现：**

```python
def _reset_for_retry(self) -> None:
    """重试时重置状态（保留重试计数器）"""
    self.status = NodeStatus.RUNNING
    self._tick_count = 0
    self._start_time = None
    self._child_index = 0
    self._children_running = False
    
    # CompositeNode 子类字段
    if hasattr(self, 'current_index'):
        self.current_index = 0
    if hasattr(self, '_last_child_finish_time'):
        self._last_child_finish_time = None
    
    # 递归重置所有子节点
    for child in self.children:
        child.reset()
```

**各组合节点的 `_reset_for_retry()` 额外重置字段：**

| 节点类型         | 额外重置字段                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------- |
| SequenceNode | `_last_child_finish_time = None`                                                                                     |
| SelectorNode | `_last_child_time = 0`                                                                                               |
| ParallelNode | `cached_statuses.clear()`                                                                                            |
| RandomNode   | `_executed_indices.clear()`, `_success_indices.clear()`, `_failure_indices.clear()`, `_current_running_index = None` |

### 1.2 复合节点 (CompositeNode)

复合节点是行为树的核心控制结构，包含多个子节点并按特定策略执行。

#### 1.2.1 顺序节点 (SequenceNode)

**语义：** 按顺序依次执行子节点，所有子节点成功才返回成功，任一失败立即返回失败。

**支持参数：**

| 参数                    | 说明             | 默认值   |
| --------------------- | -------------- | ----- |
| continue\_on\_failure | 失败后是否继续执行后续子节点 | False |
| childinterval         | 子节点执行间隔（毫秒）    | 0     |
| childinterval\_random | 子节点间隔随机范围（±毫秒） | 0     |

**实现伪代码：**

```
function SequenceNode.tick(context):
    if children is empty:
        return SUCCESS
    
    while current_index < len(children):
        child = children[current_index]
        
        if not child.config.enabled:
            current_index += 1
            continue
        
        status = child.tick(context)
        
        if status == RUNNING:
            return RUNNING          // 等待当前子节点完成
        
        if status == FAILURE:
            if continue_on_failure:
                current_index += 1  // 继续执行下一个子节点
                continue
            current_index = 0       // 重置，下次从头开始
            return FAILURE          // 短路：任一失败即失败
        
        // 子节点执行成功，添加间隔
        if childinterval > 0:
            actual_interval = get_random_duration(childinterval, childinterval_random)
            sleep(actual_interval / 1000.0)
        
        current_index += 1          // 成功则继续下一个
    
    current_index = 0               // 全部成功，重置
    return SUCCESS
```

**关键实现细节：**

- `current_index` 记录当前执行位置，支持 RUNNING 状态的记忆
- 失败时重置 `current_index = 0`，确保下次 tick 从头开始
- 跳过 `enabled = False` 的子节点

#### 1.2.2 选择节点 (SelectorNode)

**语义：** 按顺序执行子节点，任一成功即返回成功，全部失败才返回失败。

**支持参数：**

| 参数                    | 说明             | 默认值 |
| --------------------- | -------------- | --- |
| childinterval         | 子节点执行间隔（毫秒）    | 0   |
| childinterval\_random | 子节点间隔随机范围（±毫秒） | 0   |

**实现伪代码：**

```
function SelectorNode.tick(context):
    if children is empty:
        return FAILURE
    
    while current_index < len(children):
        child = children[current_index]
        
        if not child.config.enabled:
            current_index += 1
            continue
        
        status = child.tick(context)
        
        if status == RUNNING:
            return RUNNING
        
        if status == SUCCESS:
            current_index = 0       // 重置
            return SUCCESS          // 短路：任一成功即成功
        
        if childinterval > 0:
            actual_interval = get_random_duration(childinterval, childinterval_random)
            sleep(actual_interval / 1000.0)
        
        current_index += 1          // 失败则尝试下一个
    
    current_index = 0
    return FAILURE                  // 全部失败
```

#### 1.2.3 并行节点 (ParallelNode)

**语义：** 同时执行所有子节点，根据成功策略决定返回条件。

**成功策略：**

- `require_all`：所有启用的子节点成功才返回成功
- `require_one`：任一子节点成功即返回成功

**实现伪代码：**

```
function ParallelNode.tick(context):
    if children is empty:
        return SUCCESS
    
    success_count = 0
    failure_count = 0
    running_children = []
    
    for i, child in enumerate(children):
        if not child.config.enabled:
            continue
        
        // 检查缓存状态（已完成的子节点不再重复执行）
        if i in cached_statuses:
            status = cached_statuses[i]
            if status == SUCCESS: success_count += 1; continue
            if status == FAILURE: failure_count += 1; continue
        
        status = child.tick(context)
        
        if status == SUCCESS:
            cached_statuses[i] = SUCCESS
            success_count += 1
        elif status == FAILURE:
            cached_statuses[i] = FAILURE
            failure_count += 1
        elif status == RUNNING:
            running_children.append(child)
    
    // require_one 策略：任一成功即返回
    if success_policy == REQUIRE_ONE and success_count > 0:
        abort_running(context, running_children)
        return SUCCESS
    
    if running_children:
        return RUNNING
    
    // 所有子节点执行完毕
    if success_policy == REQUIRE_ALL:
        return SUCCESS if success_count == enabled_count else FAILURE
    else:
        return SUCCESS if success_count > 0 else FAILURE
```

**关键实现细节：**

- `cached_statuses` 缓存已完成子节点的状态，避免重复 tick
- `require_one` 模式下，一旦有子节点成功，立即中止其他运行中的子节点
- `reset()` 时清空缓存

#### 1.2.4 随机节点 (RandomNode)

**语义：** 随机执行子节点，根据成功策略决定返回条件。

**成功策略：**

- `require_all`：所有启用的子节点成功才返回成功
- `require_one`：任一子节点成功即返回成功

**参数配置：**

| 参数                    | 说明                              | 默认值            |
| --------------------- | ------------------------------- | -------------- |
| success\_policy       | 成功策略（require\_all/require\_one） | "require\_all" |
| continue\_on\_failure | 失败后是否继续执行（仅 require\_all 策略生效）  | False          |
| fully\_random         | 完全随机模式（True 时已执行的子节点仍可被选中）      | False          |

**关键实现细节：**

- `_executed_indices`：记录已执行的子节点索引（用于非完全随机模式）
- `_success_indices`：记录成功的子节点索引
- `_failure_indices`：记录失败的子节点索引
- `_current_running_index`：当前正在执行的子节点索引（用于恢复 RUNNING 状态）
- `fully_random=True` 时，子节点可被重复选中，直到所有子节点都执行过一次

#### 1.2.5 开始节点 (StartNode)

**语义：** 作为行为树的根节点，顺序执行所有子节点，子节点失败后继续执行后续子节点。

**与 SequenceNode 的区别：**

| 特性   | SequenceNode      | StartNode         |
| ---- | ----------------- | ----------------- |
| 失败处理 | 任一失败立即返回          | 失败后继续执行           |
| 执行模式 | 短路执行              | 全部执行              |
| 用途   | 条件序列              | 行为树根节点            |

**关键实现细节：**

- `current_index` 记录当前执行位置，支持 RUNNING 状态的记忆
- 子节点失败时设置 `has_failure = true`，但继续执行后续子节点
- **始终返回 SUCCESS**：即使有子节点失败，确保行为树可以继续执行

#### 1.2.6 子树节点 (SubtreeNode)

**语义：** CompositeNode 的子类，在运行时动态加载并执行外部行为树项目。

**参数配置：**

| 参数              | 说明          | 默认值       |
| --------------- | ----------- | ---------- |
| subtree\_path   | 子树项目路径     | ""         |
| blackboard\_mode | 黑板隔离模式     | "inherit"  |
| namespace       | 命名空间前缀     | ""         |
| auto\_reload    | 自动重载       | True       |

**关键设计要点：**

| 要点   | 说明                                                    |
| ---- | ----------------------------------------------------- |
| 延迟加载 | 首次 tick 时才加载子树，避免启动时开销                                |
| 路径解析 | 支持相对路径和绝对路径，相对路径基于 project\_root 解析                   |
| 文件查找 | 按 project.json->main\_tree / tree.json / 单一json 的优先级查找 |
| 循环检测 | 使用 CycleDetector 在加载时 DFS 检测循环引用                      |
| 黑板隔离 | 三种模式：inherit/isolated/namespaced                      |
| 状态传播 | reset() 和 abort() 自动传播到子树所有节点                         |

### 1.3 条件节点 (ConditionNode)

条件节点检测环境状态，返回 SUCCESS 或 FAILURE，不产生副作用。

**基类实现：**

```python
class ConditionNode(Node):
    def __init__(self, node_id=None, config=None):
        super().__init__(node_id, config)
        self.invert = self.config.get_bool("invert", False)  # 结果取反
        self._last_check_time = -self.config.get_int("check_interval_ms", 300) - 1
        self._children_running = False  # 子节点执行状态追踪标志
        # 智能跳过：连续相同结果时延长检测间隔
        self._consecutive_same_count = 0
        self._last_condition_result = None
        self._STABLE_THRESHOLD = 15

    def tick(self, context):
        // 检查子节点是否正在执行
        if self._children_running and self.children:
            return self._execute_children(context)

        // 检测间隔控制
        current_time = context.elapsed_time * 1000
        check_interval_ms = self.config.get_int("check_interval_ms", 300)
        if current_time - self._last_check_time < check_interval_ms:
            return self.status    // 未到检测时间，返回上次状态

        self._last_check_time = current_time
        result = self._check_condition(context)   // 子类实现

        if self.invert:
            result = not result

        status = SUCCESS if result else FAILURE
        self.status = status

        // 条件成功时执行子节点
        if status == SUCCESS and self.children:
            self._children_running = True
            return self._execute_children(context)

        return status
```

> **V1.6.1a 变更**：`__init__` 中删除了所有在 `_check_condition` 中被重新从 config 读取的实例属性（`self.check_interval_ms`、`self.save_position`、`self.position_key`、`self.offset`），改为在每次 tick 时从 config 实时读取。这消除了"初始化时读取一次、运行时又重新读取"的双数据源问题，确保运行时修改参数能立即生效。

**装饰参数（所有条件节点通用）：**

| 参数                  | 说明          | 默认值    |
| ------------------- | ----------- | ------ |
| invert              | 结果取反        | False  |
| retry\_count        | 失败重试次数      | 0      |
| timeout\_ms         | 超时时间        | 0      |
| check\_interval\_ms | 检测间隔        | 300    |
| offset              | 坐标偏移 (x, y) | (0, 0) |
| region\_mode        | 区域选择方式    | "fixed" |

**动态区域检测：**

条件节点支持两种区域选择方式，通过 `region_mode` 配置切换：

- **固定区域检测**（`"fixed"`，默认）：使用 `region` 字段指定的固定坐标区域
- **动态区域检测**（`"dynamic"`）：根据黑板锚点位置 + 偏移量动态计算检测区域

**坐标自动拆分：**

`_save_position` 方法在保存位置到黑板时，自动将坐标拆分为 x/y 分量：

```python
def _save_position(self, context, position):
    if position and hasattr(context, 'blackboard'):
        context.blackboard.set(self.position_key, position)
        context.blackboard.set("last_detection_x", position[0])
        context.blackboard.set("last_detection_y", position[1])
```

**坐标区域偏移（V1.6.1a）：**

`_adjust_position` 方法（基类统一实现）将检测到的相对坐标加上 region 偏移，转换为绝对坐标：

```python
def _adjust_position(self, position, context=None):
    if position is None:
        return None
    region = self._get_effective_region(context) if context else self._parse_region(...)
    if region:
        return (position[0] + region[0], position[1] + region[1])
    return position
```

所有条件节点（ImageConditionNode、ColorConditionNode 等）统一使用基类的 `_adjust_position` 方法，消除子类重复实现。

#### 1.3.1 文字检测节点 (OCRConditionNode)

**执行流程：**

```
1. context.get_screenshot(region)     → 获取截图
2. context.perform_ocr(image, keywords, language, preprocess_mode)  → OCR识别
3. 若找到关键词:
   - 收集所有匹配位置，按 search_direction 排序
   - blackboard.set(position_key, position)  → 记录位置
   - return True
4. 若未找到:
   - 输出识别到的所有文本内容
   - return False
```

> **V1.6.1a 变更**：`context.perform_ocr()` 新增 `preprocess_mode` 参数，支持传递预处理模式（normal/game/adaptive/auto）。此前该方法未传递预处理模式，始终使用默认的 "normal" 模式，无法利用复杂色彩、自适应等预处理能力。

**参数说明：**

| 参数                | 说明                        | 默认值           |
| ----------------- | ------------------------- | ------------- |
| region            | 检测区域                      | 全屏            |
| keywords          | 检测关键词                     | —             |
| language          | OCR语言（简体中文/English/繁体中文）  | "简体中文"        |
| preprocess\_mode  | 图像预处理模式（默认/复杂色彩/自适应/自动调优） | "默认"          |
| search\_direction | 识别方向（左上/右上/左下/右下）         | "左上"          |
| position\_key     | 位置保存的黑板变量名                | ""（空时使用全局默认值） |
| offset            | 坐标偏移量                     | (0, 0)        |

#### 1.3.2 图像匹配节点 (ImageConditionNode)

**执行流程：**

```
1. Image.open(template_path)          → 加载模板图像（首次缓存）
2. context.get_screenshot(region)     → 获取截图
3. _resolve_scales()                  → 解析多尺度配置，未开启返回 None
4. ImageProcessor.find_template_scaled(screenshot, template, threshold, scales)
   返回: (found: bool, position: Optional[Tuple], confidence: float, best_scale: float)
5. 若匹配成功:
   - actual_position = _adjust_position(position, context)  → 换算为屏幕绝对 / 客户区坐标
   - blackboard.set(position_key, actual_position)  → 记录位置
   - 缩放比非 1.0 时日志附带 scale
   - return True
6. 若匹配失败:
   - 输出置信度和阈值信息
   - return False
```

**V2.0.0 匹配判定重构**

原实现单用 `TM_CCOEFF_NORMED`，在纯色区域会因标准差为 0 出现 0/0 塌缩——整幅响应急全为 1.0，`minMaxLoc` 必然返回 `(0,0)`，于是"纯色画面 + 纯色模板"被当成满分匹配。重构为三步：

| 阶段 | 方法 | 作用 |
| --- | --- | --- |
| 定位 | `TM_SQDIFF_NORMED` | 数值稳定，不会出现 0/0；取响应最小值位置 |
| 打分 | 局部皮尔逊相关 | 对线性亮度变化免疫，只反映结构相关性；不像 SQDIFF 那样因整帧灰度差给出虚高分数 |
| 纹理门 | Sobel 梯度均值 `_edge_energy()` | 模板或命中区域边缘能量低于 `MIN_EDGE_ENERGY = 3.0` 时直接拒绝，并给出原因 |

> 为什么不用标准差做纹理门：实测真实截图纯色区标准差可达 5.14（压缩噪点），用 std 判断会把有噪点的纯色区放过去；Sobel 梯度均值对"平坦但有噪声"更敏感。

**多尺度匹配（V2.0.0）**

`ImageProcessor.build_scales((low, high), steps)` 在范围内均匀取 `steps` 档；若范围包含 1.0 但取出的档位没有正好落在 1.0，则补入 1.0 后重排，避免丢掉原始尺寸这一档。`find_template_scaled` 逐档用 `Image.LANCZOS` 缩放模板（缩放后超出源图尺寸的档直接跳过）后调用单尺度匹配，保留置信度最高的一档及其缩放比。

> 代价是线性的：每多一档就多一次全图 `matchTemplate`。实测单档 191ms 中缩放本身只占 0.4%（0.7ms），开销全在匹配——因此该选项只在确有 DPI / 显示缩放差异时开启。

**find_template 输入校验与格式兼容（V1.6.1a）：**

`find_template` 方法在匹配前进行输入校验和格式统一：
- **格式统一**：自动将灰度图（单通道）、RGBA（四通道）统一转换为 RGB 三通道，避免 `cv2.matchTemplate` 因通道不匹配崩溃
- **尺寸校验**：源图小于模板时返回 `(False, None, 0.0)` 而非抛出异常
- **灰度匹配**：内部统一转灰度图后进行 `TM_CCOEFF_NORMED` 匹配

**find_by_hash 粗-细两阶段搜索（V1.6.1a）：**

`ImageProcessor.find_by_hash` 使用粗-细两阶段搜索策略，替代原有的固定 10x10 步长稀疏采样：
- **粗搜索**：以模板尺寸的 1/4 为步长进行网格扫描，记录汉明距离 <= 阈值的候选点
- **精搜索**：在粗搜索命中点周围 ±1 步长范围内逐像素搜索，找到最佳匹配
- **模板哈希缓存**：使用 `_template_hash_cache` 类变量缓存模板哈希值，缓存键为模板 phash + hash_type，避免行为树 tick 场景下重复计算
- **返回值统一**：未找到时返回 `(False, None, None)`，找到时返回 `(True, position, index)`

**参数说明：**

| 参数             | 说明                 | 默认值           |
| -------------- | ------------------ | ------------- |
| region         | 检测区域               | 全屏            |
| template\_path | 模板图像路径             | —             |
| threshold      | 匹配阈值（支持百分比和小数两种格式） | 0.8           |
| position\_key  | 位置保存的黑板变量名         | ""（空时使用全局默认值） |
| multi\_scale   | 是否启用多尺度匹配          | false         |
| scale\_range   | 缩放范围 `low,high`    | `0.85,1.15`   |
| scale\_steps   | 缩放档数               | 5             |

**threshold 参数兼容性：** 百分比格式 `65` 表示 65%，自动转换为 `0.65`；小数格式 `0.65` 直接使用。

#### 1.3.3 颜色检测节点 (ColorConditionNode)

**执行流程：**

```
1. context.get_screenshot(region)     → 获取截图
2. ImageProcessor.find_color(screenshot, target_color, tolerance,
        match_mode=match_mode, match_ratio=color_match_threshold)  → 颜色搜索
3. 若找到匹配颜色:
   - actual_position = _adjust_position(position, context)  → 加上区域偏移
   - blackboard.set(position_key, actual_position)  → 记录位置
   - return True
4. 若未找到: return False
```

**find_color 统一实现（V1.6.1a）：**

`ColorConditionNode` 不再自行实现颜色检测逻辑，改为统一调用 `ImageProcessor.find_color`，支持两种匹配模式：
- **any 模式**（默认）：任一像素匹配即可，需达到 `min_pixels` 最小匹配数
- **all 模式**：匹配像素占比需达到 `color_match_threshold` 阈值（默认 0.9），用于检测区域是否主要由某颜色构成（如血条是否满、背景是否为特定颜色）。此前 all 模式使用 `np.all(matches)` 要求全部像素匹配，因抗锯齿边缘和压缩噪点几乎永远返回 False，无实用价值
- 位置返回匹配像素的中位数位置

**参数说明：**

| 参数            | 说明         | 默认值           |
| ------------- | ---------- | ------------- |
| region        | 检测区域       | 全屏            |
| target\_color | 目标颜色       | —             |
| tolerance     | 颜色容差       | 30            |
| match\_mode   | 匹配模式（any/all） | "any"      |
| min\_pixels   | any 模式最小匹配像素数 | 1          |
| color\_match\_threshold | all 模式匹配占比阈值 | 0.9  |
| position\_key | 位置保存的黑板变量名 | ""（空时使用全局默认值） |

**target_color 解析顺序（V2.0.0）**

`ConditionNode._parse_color()` 按以下顺序尝试，命中即返回：

1. `RGB(r,g,b)` 函数式（大小写不敏感）
2. `#RRGGBB` / `RRGGBB` —— 六位十六进制，最常用
3. `#RGB` —— 三位简写，每位字符翻倍展开（`#f00` → `(255,0,0)`）
4. `r,g,b` 逗号三元组 —— 兼容旧配置

全部失败时回退 `(255,0,0)`。新增的十六进制分支解决了「属性面板颜色选择器输出 `#RRGGBB`，而解析器只认 RGB 函数式，导致用户选完颜色仍按红色检测」的隐性错误。

#### 1.3.4 数字比较节点 (NumberConditionNode)

**执行流程：**

```
1. context.get_screenshot(region)     → 获取截图
2. OCRManager.recognize_number_with_position(...)  → 数字OCR
3. 若识别成功:
   - 收集所有数字位置，按 search_direction 排序
   - blackboard.set("last_number_value", value)
   - blackboard.set(position_key, position)
   - blackboard.set(value_key, value)
   - OPERATORS[compare_mode](value, threshold)  → 比较运算
4. 若识别失败: return False
```

**参数说明：**

| 参数                | 说明                      | 默认值                   |
| ----------------- | ----------------------- | --------------------- |
| region            | 检测区域                    | 全屏                    |
| preprocess\_mode  | 图像预处理（默认/复杂色彩/自适应/自动调优） | "默认"                  |
| extract\_mode     | 提取模式（无规则/x/y/自定义）       | "无规则"                 |
| extract\_pattern  | 自定义提取模式（使用\*作为通配符）      | ""                    |
| compare\_mode     | 比较运算符（>、<、>=、<=、==、!=）  | ">"                   |
| threshold         | 比较目标值                   | 0                     |
| min\_confidence   | 最小置信度                   | 0.5                   |
| search\_direction | 识别方向（左上/右上/左下/右下）       | "左上"                  |
| value\_key        | 数字值保存的黑板变量名             | "last\_number\_value" |
| position\_key     | 检测位置保存的黑板变量名            | ""（空时使用全局默认值）         |
| offset            | 坐标偏移量（相对偏移）             | (0, 0)                |

#### 1.3.5 变量判断节点 (VariableConditionNode)

**语义：** 判断黑板变量是否满足指定条件，支持常量值比较、变量间比较和存在性判断。

**支持参数：**

| 参数 | 说明 | 默认值 |
|------|------|--------|
| variable_name | 要判断的黑板变量名 | "" |
| operator | 比较运算符（==, !=, >, >=, <, <=, exists, not_exists） | "==" |
| compare_type | 比较值类型（常量值/变量名） | "constant" |
| compare_value | 比较值（常量值模式时显示） | "" |
| compare_variable | 比较变量（变量名模式时显示） | "" |

**关键实现细节：**

- `compare_type == "variable"` 时，比较值从黑板动态获取，保留原始类型
- 比较变量不存在或值为 None 时，显式返回 False 并输出日志
- `exists/not_exists` 运算符仅调用 `blackboard.exists()`，不获取变量值

#### 1.3.6 文本提取节点 (TextExtractNode)

**语义：** 通过 OCR 识别屏幕指定区域的文字内容，提取文本并保存到黑板变量。

**执行流程（V1.6.1a 优化后）：**

```
1. context.get_screenshot(region)     → 获取截图
2. ocr_manager.recognize_with_boxes(screenshot, language, preprocess_mode)
   → 单次 OCR 调用，同时获取文本内容和位置信息
3. 从 boxes_result 提取全部文本: all_text = "\n".join(text for text, _, _ in boxes_result)
4. 根据 extract_mode 提取目标文本:
   - all 模式: extracted_text = all_text
   - keywords 模式: extracted_text = _extract_keywords_text(all_text, keywords)
5. blackboard.set(output_key, extracted_text)  → 保存提取结果
6. 若 save_position:
   - 从已有 boxes_result 中查找关键词位置（_find_keyword_position）
   - 找到: 保存精确位置 + last_detection_x/y
   - 未找到: 使用区域中心作为回退位置 + last_detection_x/y
7. return True/False
```

> **V1.6.1a 变更**：
> 1. **消除重复 OCR 调用**：此前先调用 `get_all_text()` 获取文本，再调用 `recognize_with_boxes()` 获取位置，对同一张图像执行了两次完整 OCR。现在改为单次 `recognize_with_boxes` 调用，从结果中同时提取文本和位置，性能提升约 40-50%。
> 2. **回退路径补写坐标分量**：当 OCR 未找到关键词位置、使用区域中心作为回退时，此前仅写入 `position_key`，遗漏了 `last_detection_x` / `last_detection_y`。现在回退路径也正确写入这两个变量，与正常路径行为一致。

**支持参数：**

| 参数               | 说明                   | 默认值                   |
| ---------------- | -------------------- | --------------------- |
| region           | 检测区域                 | None                  |
| extract\_mode    | 提取模式（all/keywords）   | all                   |
| keywords         | 关键词（keywords模式时使用）   | ""                    |
| language         | OCR识别语言              | chi\_sim              |
| preprocess\_mode | 图像预处理模式（normal/game） | normal                |
| output\_key      | 提取文本输出变量名            | last\_extracted\_text |
| save\_all\_text  | 是否保存全部OCR文本          | False                 |
| all\_text\_key   | 全部文本变量名              | all\_ocr\_text        |
| save\_position   | 是否保存检测位置             | True                  |
| position\_key    | 位置变量名                | ""（空时使用全局默认值）         |
| offset           | 坐标偏移                 | (0, 0)                |

### 1.4 动作节点 (ActionNode)

动作节点执行具体操作，产生副作用。

**基类实现：**

```python
class ActionNode(Node):
    def __init__(self, node_id=None, config=None):
        super().__init__(node_id, config)
        self._children_running = False  # 子节点执行状态追踪标志
    
    def tick(self, context):
        if self._children_running and self.children:
            return self._execute_children(context)
        
        status = self._execute_action(context)   // 子类实现
        self.status = status
        
        if status == SUCCESS and self.children:
            context.notify_node_status(self.node_id, "success")
            self._children_running = True
            return self._execute_children(context)
        
        return status
```

**装饰参数（所有动作节点通用）：**

| 参数            | 说明   | 默认值 |
| ------------- | ---- | --- |
| repeat\_count | 重复次数 | 0   |
| timeout\_ms   | 超时时间 | 0   |

**随机范围参数（部分动作节点支持）：**

| 节点             | 参数              | 随机范围参数                  |
| -------------- | --------------- | ----------------------- |
| DelayNode      | duration\_ms    | duration\_ms\_random    |
| MouseClickNode | click\_interval | click\_interval\_random |
| MouseMoveNode  | move\_duration  | move\_duration\_random  |
| KeyPressNode   | duration        | duration\_random        |

**随机值计算函数：**

```python
def get_random_value(base_value: int, random_range: int = 0, min_value: int = None) -> int:
    if random_range <= 0:
        return base_value
    min_val = base_value - random_range
    max_val = base_value + random_range
    if min_value is not None:
        min_val = max(min_val, min_value)
    return random.randint(int(min_val), int(max_val))
```

#### 各动作节点实现要点

| 节点              | 核心调用                                                              | 关键参数                                                                                                                                                                                               |
| --------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| KeyPressNode    | `context.execute_key_press(key, action, duration)`                | key, action(press/down/up), duration, duration\_random                                                                                                                                             |
| MouseClickNode  | `context.execute_mouse_click(button, position, action, duration)` | button, position, click\_count(-1=无限点击), click\_interval, click\_interval\_random                                                                                                                  |
| MouseMoveNode   | `context.execute_mouse_move(position, relative)`                  | position, use\_blackboard, position\_key, move\_type(移动/拖拽), drag\_button, relative(增量移动), offset, end\_position, use\_blackboard\_end, position\_key\_end, move\_duration, move\_duration\_random |
| MouseScrollNode | `context.execute_mouse_scroll(...)`                               | distance, clicks, direction                                                                                                                                                                        |
| DelayNode       | `time.sleep()` + 状态记忆                                             | duration\_ms, duration\_ms\_random, \_start\_time                                                                                                                                                  |
| SetVariableNode | `blackboard.set/increment/delete()` | variable\_name, operation(set/increment/delete), value\_type(constant/variable), value, source\_variable |
| ScriptNode      | `ScriptExecutor.run_script()`                                     | script\_path, loop                                                                                                                                                                                 |
| CodeNode        | `subprocess.run/Popen()`                                          | code\_path, args, wait\_complete                                                                                                                                                                   |
| AlarmNode       | `AlarmPlayer.play()`                                              | sound\_path, volume, wait\_complete                                                                                                                                                                |
| TextInputNode   | pyperclip + Ctrl+V 逐字符输入                                       | input\_mode(extracted/preset/file), preset\_texts, execution\_mode, blackboard\_key, file\_path, input\_delay, clear\_before\_input                                                                   |
| StartTreeNode   | `tab_manager.start_tab()`                                         | target\_tree, sound\_path, volume                                                                                                                                                                  |
| StopTreeNode    | `tab_manager.stop_tab()`                                          | target\_tree, sound\_path, volume                                                                                                                                                                  |

**MouseClickNode 无限点击功能：** `click_count = -1` 时进入无限点击模式，持续点击直到行为树停止。

**MouseMoveNode 移动/拖拽功能：**

| 参数                     | 说明                 | 默认值           |
| ---------------------- | ------------------ | ------------- |
| move\_type             | 操作类型（移动/拖拽）        | "移动"          |
| drag\_button           | 拖拽按键（移动模式时隐藏）      | "left"        |
| relative               | 增量移动模式             | False         |
| offset                 | 增量值（增量移动时显示）       | (0, 0)        |
| move\_duration         | 移动时长（毫秒）           | 0             |
| move\_duration\_random | 移动时长随机范围（±毫秒）      | 0             |

当 `move_duration > 0` 时，使用 smoothstep 缓动函数实现平滑移动；`move_duration = 0` 时瞬间移动。

**DelayNode 特殊实现：** DelayNode 是唯一可能返回 RUNNING 状态的动作节点。它使用 `_start_time` 记录开始时间，在 `duration_ms` 内持续返回 RUNNING，超时后返回 SUCCESS 并重置。

**ScriptNode 实例级执行器隔离：** 多 Tab 并行时，ScriptNode 使用实例级执行器（`_executor`），确保互不影响。`delay` 命令使用分段 sleep 支持中断。

**StartTreeNode / StopTreeNode：** 用于启动/停止其他已加载的行为树。`SKIP_WINDOW_SWITCH = True`，不触发窗口切换。`target_tree` 为空时操作当前行为树。

## 2 节点间通信机制

### 2.1 日志管理器 (LogManager)

LogManager 采用单例模式，提供统一的日志接口：

```python
class LogManager:
    _instance = None
    
    @classmethod
    def instance(cls) -> "LogManager":
        if cls._instance is None:
            cls._instance = cls()
        return cls._instance
    
    def log_success(self, node_type: str, node_name: str) -> None:
    def log_failure(self, node_type: str, node_name: str, reason: str = "") -> None:
    def log_aborted(self, node_type: str, node_name: str) -> None:
```

**日志级别：** SUCCESS(绿色)、FAILURE(红色)、ABORTED(橙色)、INFO(蓝色)

```python
blackboard.subscribe("last_detection_position", on_position_change)
```

## 5 输入系统实现

### 5.1 多引擎输入架构

系统支持 4 种输入引擎，键盘和鼠标引擎可独立选择：

| 引擎               | 类型   | InputLevel   | 说明                     |
| ---------------- | ---- | ------------ | ---------------------- |
| PyAutoGUI         | 键盘+鼠标 | APPLICATION  | 标准 Python 库，应用层输入       |
| DD                | 键盘+鼠标 | DRIVER       | DD虚拟键盘驱动，驱动层输入         |
| IbInputSimulator  | 键盘+鼠标 | DRIVER       | IB驱动模拟，支持多种驱动子模式       |
| Background        | 键盘+鼠标 | BACKGROUND   | PostMessage 后台输入，需绑定窗口  |

**配置方式：**

```yaml
input:
  keyboard_method: "pyautogui"   # pyautogui | dd | ib | background
  mouse_method: "pyautogui"      # pyautogui | dd | ib | background
```

**架构层次：**

```
ExecutionContext
    ├── InputControllerManager.get_keyboard_engine()
    │     ├── PyAutoGUIKeyboardController
    │     ├── DDKeyboardController
    │     ├── IBKeyboardController
    │     └── BackgroundKeyboardController
    └── InputControllerManager.get_mouse_engine()
          ├── PyAutoGUIMouseController
          ├── DDMouseController
          ├── IBMouseController
          └── BackgroundMouseController
```

### 5.2 IbInputSimulator 关键 API

**DLL API：**

```
IbSendInit(send_type, mode, args)    // 初始化，send_type 选择驱动子模式
IbSendInputHook(mode)                // Hook 开关：1=ON, 0=OFF
IbSendDestroy()                      // 销毁，释放资源
```

**send_type 映射：**

| send_type | 驱动模式       | 说明                   |
| --------- | ---------- | -------------------- |
| 0         | AnyDriver  | 自动选择可用驱动             |
| 1         | SendInput  | Win32 SendInput，移除注入标志 |
| 2         | Logitech   | 罗技驱动模拟               |
| 3         | Razer      | 雷蛇驱动模拟               |
| 5         | MCII       | 内核级鼠标注入，需目标 PID      |
| 6         | GHubNew    | 罗技 G Hub 新版驱动        |

**Hook 机制：** 每次输入操作：`IbSendInputHook(1)` → `SendInput(...)` → `IbSendInputHook(0)`。Hook 拦截 SendInput 调用，移除 `injected` 标志。

**ctypes 调用约定：** IB DLL 使用 `__cdecl` 调用约定，加载方式为 `ctypes.cdll.LoadLibrary(dll_path)`。

### 5.3 后台输入实现

BackgroundInputController 基于 Win32 PostMessage 实现，无需前台窗口焦点。坐标使用客户区坐标（非屏幕坐标），通过 `ScreenToClient(hwnd, point)` 转换。

**前置条件：** 必须绑定目标窗口（hwnd），通过 `input.window_hwnd` 配置。

### 5.4 DD虚拟键盘实现

**DLL 加载搜索路径优先级：** 构造参数 → `bt_utils/DD64.dll` → `bt_utils/drivers/DD64.dll` → `../drivers/DD64.dll` → 项目根/drivers/DD64.dll

**按键转换链：** `key_name → VK_CODE_MAP → vk_code → DD_todc(vk_code) → dd_code`

### 5.5 InputControllerFactory

输入控制器工厂负责根据配置创建对应的输入引擎实例，文件路径为 `bt_utils/input_controller_factory.py`。

## 6 画布编辑器实现

### 6.1 坐标系统

画布使用三层坐标变换：

```
screen_x = world_x * zoom + pan_x
screen_y = world_y * zoom + pan_y

world_x = (screen_x - pan_x) / zoom
world_y = (screen_y - pan_y) / zoom
```

### 6.2 节点渲染

NodeItem 在 Tkinter Canvas 上绘制，包含阴影、主体矩形、左侧分类色条、节点名称、状态指示器、输入/输出端口等视觉元素。

### 6.3 连线渲染

连线使用贝塞尔曲线风格的三段折线（垂直段→水平段→垂直段）。

### 6.3.1 Canvas 虚拟化

为支持数百节点流畅交互，画布新增虚拟化渲染机制，仅渲染视口内可见节点。拖拽节点时仅重绘关联连线，使用 `_node_connections_map` 反向索引。

### 6.4 连接验证机制

画布在创建连接时进行严格验证：

1. 检查节点是否存在
2. 检查是否已经存在相同的连接
3. 检查子节点是否已经有父节点
4. 检查是否会形成循环（DFS 算法）

连接失败时通过日志管理器输出提示信息，不使用弹窗干扰用户操作。

### 6.5 自动布局

当加载的树数据不包含位置信息时，使用递归自动布局，基于子树宽度计算节点位置。

### 8.1 RapidOCR 引擎初始化

### 8.2 图像预处理模式

| 模式             | 处理流程                    | 适用场景      |
| -------------- | ----------------------- | --------- |
| normal (默认)    | 灰度→对比度增强→锐化→二值化         | 标准文字识别    |
| game (复杂色彩)    | 放大→中值滤波→灰度→对比度增强→锐化→二值化 | 游戏界面、小字体  |
| adaptive (自适应) | CLAHE对比度增强→自适应二值化       | 低对比度、渐变背景 |
| auto (自动调优)    | 根据图像特征自动选择最佳预处理参数       | 所有场景，推荐使用 |

**PreprocessConfig 工厂模式（V1.6.1a）：**

预处理配置使用工厂模式统一管理，替代原有的 3 个硬编码预处理方法：
- `PreprocessConfig.standard()` — 标准文字预处理（等价于原 `_preprocess_normal`）
- `PreprocessConfig.chinese(scale_factor)` — 中文/游戏界面预处理（等价于原 `_preprocess_chinese`）
- `PreprocessConfig.adaptive()` — 自适应预处理（等价于原 `_preprocess_adaptive`）

工厂方法返回 `PreprocessConfig` 数据类实例，包含完整的预处理参数（放大倍数、降噪方法、对比度增强、锐化、二值化等），由统一的 `_apply_preprocess` 方法执行。

### 8.3 结果缓存机制

OCRManager 内置线程安全的结果缓存（V1.6.1a 优化）：

- **LRU + TTL 双重淘汰**：使用自定义 `LRUCache` 类，支持 O(1) 淘汰和 TTL 过期
- **TTL 过期**：缓存超过 3 秒自动失效（从 1 秒提升）
- **LRU 淘汰**：缓存条目超过 200 条时淘汰最旧的
- **线程安全**：使用 `threading.Lock` 保护缓存操作
- **命中率统计**：内置 `_hits` / `_misses` 计数器，支持缓存命中率监控
- **缓存键优化**：基于图像感知哈希（phash）和参数哈希计算，替代原 MD5 计算开销

### 8.4 图像特征分析器

`ImageFeatureAnalyzer` 自动分析图像特征（亮度、对比度、噪点水平、字符高度、背景类型等），为预处理决策提供依据。

### 8.5 智能放大策略

`SmartScaleStrategy` 基于字符高度计算安全的放大倍数（最大 4 倍），使用 Lanczos 高质量插值放大图像。

### 8.6 自动配置选择器

`AutoConfigSelector` 根据图像特征自动选择最佳预处理参数，按优先级处理：噪点 > 低对比度 > 深色背景 > 渐变背景 > 小字体。

### 8.7 精确关键词定位

基于字符实际宽度系数（中文 2.0、大写 1.2、小写 1.0、数字 1.0 等）精确计算关键词在文本行中的位置，解决中英混合文本定位偏差问题。

**V2.0.0：区分「只读安装内容」与「可写用户目录」**

`get_resource_path()` 只解决"读内置资源"，无法表达"该写到哪里"。V2.0.0 新增三个函数，把路径语义补全：

```python
def get_app_home() -> str:
    """可写主目录：开发环境=项目根，打包环境=exe 所在目录"""
    if getattr(sys, 'frozen', False):
        return os.path.dirname(os.path.abspath(sys.executable))
    return os.path.dirname(os.path.dirname(os.path.abspath(__file__)))


def get_builtin_plugins_dir() -> str:
    """内置插件（随包分发，只读）"""
    return os.path.join(get_app_root(), "bt_plugins", "builtin")


def get_user_plugin_dir() -> str:
    """用户插件（可写）：env 覆盖优先，否则 <app_home>/plugins"""
    env_dir = os.environ.get("AUTODOOR_PLUGINS_DIR")
    if env_dir:
        return os.path.abspath(env_dir)
    return os.path.join(get_app_home(), "plugins")
```

## 14 UI 更新分发器实现（防止假卡死）

### 14.1 问题背景

tkinter 的 GUI 操作必须在主线程执行，但行为树引擎在独立线程中运行。直接从后台线程调用 tkinter 可能导致界面假卡死。

### 14.2 核心解决方案

采用**定时轮询 + 后台守护**混合模式：

- 运行时 10ms 轮询间隔，空闲时 100ms 轮询间隔
- 轮询必须在编辑器初始化时启动，而不是运行时启动
- **不要停止轮询**，让它持续运行
- 当 `_widget` 为 None 时，使用后台线程守护，等待 `_widget` 可用

### 14.3 防止假卡死的关键要点

| 问题                  | 错误做法                       | 正确做法                            |
| ------------------- | -------------------------- | ------------------------------- |
| 启动时假卡死              | 在 `_start_running()` 中启动轮询 | 在 `_init_ui_dispatcher()` 中启动轮询 |
| 手动停止后异常             | 停止时调用 `stop_polling()`     | **不要停止轮询**，让它持续运行               |
| 轮询永久停止              | `_widget` 为 None 时直接返回     | 使用后台线程守护，等待 `_widget` 可用        |

## 22 视觉素材清单与 assets 命令（V2.0.0）

### 22.1 为什么需要清单

模板匹配的输入不止一张图：还需要"这张图是从哪张源图的哪个位置裁的、对应屏幕上哪一块、主色是什么、语义是什么"。这些东西散落在对话、截图、笔记里，一旦要迁移工程或重做素材就全部丢失。`assets/manifest.json` 把这些字段固化下来，`assets verify` 则能在运行前发现"模板文件被删了""尺寸被改了"这类问题。

### 22.2 产物结构

```
<项目根>/
├── assets/
│   ├── manifest.json          # 清单（version + targets[]）
│   ├── templates/<name>.png   # 裁剪出的模板图
│   └── raw/screen_<ts>.png    # --capture 直接截屏时的原始截图
```

单条 target（`kind = "template"`）：

| 字段 | 说明 |
| --- | --- |
| `name` | 素材名，同时是模板文件名 |
| `semantic` | 语义描述，供人工核对与追溯 |
| `template` / `template_size` | 模板相对路径与实际尺寸 |
| `bbox_image` | 模板在**源图内**的裁剪框 |
| `bbox_screen` / `center_screen` | 换算后的屏幕绝对坐标与中心点 |
| `coord_client` | 窗口客户区相对坐标（给了 `--hwnd` / `--offset` 才有） |
| `anchor` | 锚点，`center` 或 `topleft` |
| `dominant_color` / `color_ratio` | 主色与占比，可直接给颜色检测节点用 |
| `source_image` / `source_origin` | 源图路径，以及源图左上角对应的屏幕坐标 —— **坐标换算的唯一依据** |
| `hwnd` | 目标窗口句柄 |
| `updated_at` | 更新时间（同日重复登记按 name 覆盖） |

UIA 采样写入的条目 `kind = "anchor"`，没有模板图，只有 `coord_client` / `center_screen` / `control_type`。

### 22.3 add 的执行链路

```
_resolve_source()          # --capture 截屏（all_screens=True）或 --source 读文件
                           # 同时确定 origin：源图左上角对应的屏幕坐标
  → (可选) refine_bbox()   # 给定 --refine-color，在粗框外扩 N 倍范围内按颜色连通域重算紧包围盒
  → crop()                 # 按 --bbox 裁剪
  → save()                 # 写 assets/templates/<name>.png
  → _dominant_color()      # 量化后统计众数颜色，给出占比
  → 坐标换算                # bbox_screen = bbox + origin；center = 四边中点
  → _to_client()           # 有 hwnd 用客户区原点，有 offset 直接用，都没有则不写
  → 写 manifest            # 同 name 覆盖，保留 created_at
```

> 坐标换算完全依赖 `origin`，这也是 `--origin` 参数存在的理由：源图若是从屏幕某处截的，必须告诉工具"这张图左上角在屏幕的哪里"，否则算出来的屏幕坐标只是图像内坐标。

### 22.4 verify 的检查项

| 级别 | 检查 |
| --- | --- |
| ERR | 名称重复；模板文件缺失或无法打开；模板实际尺寸与 `template_size` 不符；`bbox_screen` 缺失、格式非法或宽高非正 |
| ERR | `dominant_color` 不是合法十六进制（`kind=anchor` 时检查坐标与控件类型） |
| WARN | `bbox_screen` 宽高与模板尺寸不一致（通常是先改了模板没更新坐标）；缺少主色（无法用颜色节点）；缺少语义描述（不可追溯） |

返回码：有 ERR 时退出码 1，可直接用于 CI / 发布前门禁。

## 23 插件加载器实现（V2.0.0）

### 23.1 三个关键动作

```python
# 1) sys.path 注入：让插件内的绝对包导入可用
_plugins_root = os.path.dirname(os.path.abspath(plugin_dir))   # .../plugins
_import_root = os.path.dirname(_plugins_root)                  # 项目根 / exe 目录
if _import_root and _import_root not in sys.path:
    sys.path.insert(0, _import_root)

# 2) 按文件路径导入入口模块，不要求插件是合法包名
spec = importlib.util.spec_from_file_location(f"bt_plugin_{name}", entry_path)
module = importlib.util.module_from_spec(spec)
spec.loader.exec_module(module)

# 3) 实例化 plugin.json 指定的类
plugin_cls = getattr(module, info.class_name)
plugin = plugin_cls(context)
```

### 23.2 为什么必须在 loader 里注入 sys.path

插件作者普遍这样写：

```python
from plugins.vlm_vision.nodes import VLMLocateNode
```

开发环境能跑，是因为 cwd 恰好是项目根、且被加进了 `sys.path`。打包成 exe 后 cwd 是 exe 所在目录，`plugins` 不在任何 `sys.path` 条目下，导入立即失败并报 `No module named 'plugins'`。在 loader 里显式注入父目录后，`plugins` 作为命名空间包（PEP 420，无需 `__init__.py`）即可解析，两种环境行为一致。

### 23.3 抽象方法陷阱

Plugin 基类的 `_check_condition(self, context)` 是 `@abstractmethod`。若插件里误写成 `_check(self, context)`，类不会在定义时报错，而是在**实例化时**抛 `TypeError: Can't instantiate abstract class ... with abstract method _check_condition`。这个报错发生在加载阶段，日志里表现为"插件加载失败"，排查时应先对照基类方法名。

### 23.4 加载失败的定位顺序

1. `plugin.json` 是否存在、字段是否齐全（尤其 `entry` 与 `class`）
2. 入口文件能否 `exec_module`（语法错误、依赖缺失都在这步暴露）
3. 类名是否与 `plugin.json` 一致、是否为 Plugin 子类
4. 实例化是否抛 `TypeError`（抽象方法未实现）
5. `start_plugin` 注册的节点类型是否与 `{插件名}.` 前缀一致

## 24 多显示器坐标换算（V2.0.0 修复）

### 24.1 三种情形的判定顺序

`ConditionNode._adjust_position(position, context)` 现在按以下顺序判定：

| 顺序 | 条件 | 处理 |
| --- | --- | --- |
| 1 | 配置了 `region` | 截图是该 region 的裁剪，图像原点 = region 左上角，直接加 `region[0], region[1]` |
| 2 | 未配 region，但绑定了窗口 | 截图是窗口图像，坐标是客户区相对坐标，原样返回，由 `execute_mouse_*` 换算 |
| 3 | 未配 region，也未绑窗口 | 截图是**整个虚拟桌面**，图像原点对应虚拟桌面左上角 `(min_x, min_y)`，需补偿 |

### 24.2 缺陷成因

`ImageGrab.grab(all_screens=True)` 返回的图像覆盖整个虚拟桌面，其左上角是 `min_x, min_y`（所有显示器边界的最小值）。副屏挂在主屏左侧时 `min_x = -1920`，挂在主屏上方时 `min_y` 为负。

原实现只做了 `position + region` 与"无 region 直接返回"，没有补偿 `min_x/min_y`，于是整屏检测到的点击位置整体偏移 `1920` 像素——**不会报错，只会点错**。同时 `_get_fallback_region()` 用 `max(0, cx - r)` 钳制边界，会把副屏上的区域裁到主屏内。

### 24.3 修复要点

```python
def _adjust_position(self, position, context=None):
    region = self._get_effective_region(context) if context else self._parse_region(...)
    if region:
        return (position[0] + region[0], position[1] + region[1])

    if context is not None and getattr(context, "get_bound_window", None):
        if context.get_bound_window():
            return position          # 客户区相对坐标，交给鼠标节点换算

    min_x, min_y, _, _ = get_virtual_screen_bounds()
    if min_x or min_y:
        return (position[0] + min_x, position[1] + min_y)
    return position
```

`_get_fallback_region()` 同步改为：

```python
min_x, min_y, max_x, max_y = get_virtual_screen_bounds()
return (max(min_x, cx - r), max(min_y, cy - r),
        min(max_x, cx + r), min(max_y, cy + r))
```

### 24.4 回归测试

`tests/test_multimonitor_coords.py` 用 monkeypatch 注入虚拟桌面边界（主屏 `(0,0)-(1920,1080)` + 左侧副屏 `(-1920,360)-(-960,1440)`），覆盖 12 个用例：整屏检测、区域检测、绑定窗口、fallback 区域边界、负原点补偿方向等。该测试不依赖真实多显示器硬件，可在 CI 中运行。
