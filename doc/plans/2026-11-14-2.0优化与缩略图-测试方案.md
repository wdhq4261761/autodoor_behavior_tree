Expected: 基线全绿（当前 548 passed）。若基线不绿，先修复环境，不进入本轮验证。

### 2.3 测试数据约定

- 临时目录一律使用 pytest `tmp_path`
- 图片统一用 Pillow 生成（`Image.new`），不提交二进制测试资源

  ```python

  ```
  或标记 `@pytest.mark.skipif(os.environ.get("CI") == "true", reason="no display")`

## 三、自动化测试设计

### 3.1 预检核心 `tests/test_preflight.py`

| 用例 | 输入 | 期望 |
|---|---|---|
| `test_empty_tree_is_error` | `{"nodes": {}}` | `EMPTY_TREE`，`has_errors=True` |
| `test_missing_root_is_error` | 根节点 id 不存在 | `ROOT_MISSING` |
| `test_unknown_node_type_is_error` | `NoSuchNode` | `UNKNOWN_NODE_TYPE` + 节点 id |
| `test_multiple_parents_is_error` | 两父指向同一子 | `MULTI_PARENT` |
| `test_cycle_is_error` | a→b→a | `CYCLE` |
| `test_unreachable_node_is_warning` | 孤立节点 | `UNREACHABLE`，`has_errors=False` |
| `test_invalid_connection_endpoint_is_error` | 连线指向不存在的节点 | `BAD_CONNECTION` |
| `test_missing_template_path_is_error` | `./images/none.png` | `MISSING_RESOURCE` |
| `test_existing_template_path_passes` | 真实存在文件 | 无 `MISSING_RESOURCE` |
| `test_subtree_missing_is_error` | `subtree_path` 不存在 | `MISSING_RESOURCE` 且 node_id 正确 |
| `test_empty_template_is_warning` | `template_path=""` | `EMPTY_RESOURCE`，不阻断 |
| `test_report_format_lines_contains_level_prefix` | 混合 error/warning | 含有 `[错误]` / `[警告]` |
| `test_path_resolution_backslash_and_dot` | `./images\a.png` | 正确解析（Windows 分隔符） |

**边界补充**
- 节点 config 为 `None` 或非 dict：不得抛异常，按空配置处理
- 深层环（>100 节点）不栈溢出（如需，可加递归深度保护）
- 插件节点：先 `NodeRegistry.register("demo.PluginNode", ...)`，再验证不报 `UNKNOWN_NODE_TYPE`

### 3.2 预检接入 `tests/test_preflight_integration.py`

| 用例 | 方式 | 期望 |
|---|---|---|
| Headless 缺模板 | `HeadlessRunner.run(..., check_preflight=True)`，mock 服务层 | 返回 2，stdout 含“预检未通过” |
| Headless 通过 | 资源齐全 | 继续执行（返回 0 或原语义） |
| Headless 跳过 | `check_preflight=False` | 不输出预检内容 |
| CLI 参数透传 | `cmd_run` + mock `HeadlessRunner.run` | 传 `check_preflight=True/False` |
| GUI 错误弹窗 | mock `messagebox.askyesno` 返回 False | `_handle_tab_run` 返回 False，不启动引擎 |
| GUI 警告放行 | 仅 warning | 不弹窗，记录日志，继续运行 |

> GUI 用例通过构造轻量 panel 或直接调用 `_handle_tab_run`（mock `tab_manager`/`canvas`）实现；不启动完整主窗口。

## 四、手工测试清单

### 4.1 预检（GUI）

1. 新建空工程，直接点运行 → 弹“行为树为空”
2. 删除模板图片后运行 → 弹错误，选择“否”不启动；选择“是”继续（旧行为可用）
3. 仅孤立节点（warning）→ 不弹窗，日志出现警告
4. 插件节点工程 → 不误报“未知节点类型”
5. 循环连线工程 → 提示循环引用

### 4.2 预检（CLI）

```powershell
venv\Scripts\python.exe cli.py run .\demo\tree.json
venv\Scripts\python.exe cli.py run .\demo\tree.json --no-preflight
```
Expected: 缺资源时第一种返回非 0 并打印中文原因；第二种跳过预检。

### 4.3 滚轮

分别将输入方式切换为 PyAutoGUI / DD / IB / BG，在记事本、浏览器、Excel 中测试：
- 向上/向下滚动幅度与系统滚轮一致（不再“一格变十格/几乎不动”）
- 向左/向右在支持横向滚动的控件（Excel、浏览器）生效
- 绑定窗口（BG）模式下滚动作用于目标窗口

### 4.4 拖拽

- 60ms、200ms、1000ms 三种时长拖拽到目标控件，落点误差 0px
- 拖拽过程中按 F12 中止 → 松开鼠标，不补终点
- 连续拖拽 20 次无“差几像素”问题

### 4.5 窗口尺寸

1. 绑定窗口运行一次 → 检查树文件 config 中出现 `window_size`
2. 手动拉伸窗口后再次运行 → 自动恢复到记录尺寸
3. 关闭“自动还原窗口尺寸” → 不再恢复
4. 最大化窗口运行 → 记录 `window_maximized=true`，但不强制取消最大化
5. 多屏/125% 缩放下重复 1-3，记录是否存在偏差（已知风险）

### 4.6 BOM

1. 用记事本另存为“UTF-8 带 BOM”的 `tree.json` → 可打开
2. `plugin.json` 带 BOM → 插件可加载
3. 工程配置 `project.json` 带 BOM → 可打开
4. 非法 JSON → 报错信息包含文件路径，不崩溃

### 4.7 缩略图

1. 图像检测节点未选图 → “未选择模板图片”
2. 选择图片 → 参数下方即时显示缩略图，比例正确不变形
3. 清空路径 → 回到占位提示
4. 删除磁盘图片后重新选中节点 → “未找到模板图片”，无异常
5. 点击缩略图 → 系统默认程序打开原图
6. 连续切换 10 个节点 → 无残留图、无内存暴涨（任务管理器观察）
7. 深色/浅色主题下缩略图背景与边框正常
